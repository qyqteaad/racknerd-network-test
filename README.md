## 测试 IP 和 Looking Glass 分别是什么

一个是从你这边测机房，一个是从机房测你这边。

**测试 IP** 是每个机房对外公开的一个 IP 地址，拿到后直接 ping 或 traceroute，就能判断你本地到这个机房的网络质量，全程不需要任何账号。

**Looking Glass** 是官方提供的在线工具，方向反过来：填入你自己的 IP，从机房那端对你的 IP 发起 ping、traceroute 或 MTR。页面还挂着 10MB、100MB、1GB 三档测速文件，浏览器直接下载就能看实际带宽。

两样配合起来，等于把线路从两个方向都过了一遍。“能不能 ping 通”只是基础，数据包走的完整路径、机房端往外推数据的速度，才是真正决定体验的部分。

## 三步测出真实延迟

光存一个 IP 没用，按这个顺序跑一遍，两分钟出结果。

### 第一步：ping 看平均延迟

在 Windows 终端或 macOS/Linux 终端里执行（以洛杉矶 DC-02 为例）：


ping 204.13.154.3


看返回结果里的平均值（avg）。移动宽带到这个节点大约在 150-180ms，联通略低一些；整体来看，洛杉矶 DC-02 到国内延迟在 170-200ms 区间属于正常，130-180ms 算优秀，超过 220ms 就要认真考虑换机房了。

### 第二步：traceroute 看路由路径

延迟只是结果，路径决定稳定性。Windows 用 `tracert`，Mac/Linux 用 `traceroute`：


tracert 204.13.154.3


重点看中间经过的节点。数据包如果在国内绕了好几圈，或者中途连续几跳超时，这条线路就不算干净，晚高峰出问题的概率也更大。

### 第三步：Looking Glass 反向测试加下载测速

前两步都是你测机房，这一步反过来。打开对应机房的 Looking Glass 页面，填入自己的 IP，选 ping 或 MTR 执行，就能看到机房往外发数据这个方向的路由质量。

测速文件也别浪费：直接下载 100MB 的文件，速度能跑满你本地宽带，说明这个机房到你这边的出口带宽没问题。想省事的话，itdog、ping.pe 这类工具能一次性从全国多个节点 ping 同一个 IP，看全国范围的延迟分布。

最后提醒一个容易忽略的点：别只测一次。早、中、晚各跑一轮 ping，尤其是晚上 8 点到 11 点——RackNerd 的延迟问题基本都集中在这个时段。
